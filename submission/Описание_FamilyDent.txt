Название программы

FamilyDent — информационная система стоматологической клиники.


Основное назначение программы

FamilyDent — полнофункциональное веб-приложение для автоматизации работы стоматологической клиники. Программа объединяет публичный сайт клиники, систему онлайн-записи, личный кабинет пациента, кабинет врача и административную панель.

Пациенты могут ознакомиться с услугами и специалистами клиники, зарегистрироваться, подтвердить адрес электронной почты, авторизоваться и самостоятельно записаться на приём. После создания записи пациент может просматривать свои посещения и данные личного кабинета.

Администратор управляет пациентами, врачами, записями, статьями и отзывами. Для врача предусмотрен отдельный защищённый интерфейс с расписанием и медицинской информацией пациентов в пределах предоставленных прав.


Основные возможности

1. Публичная часть

- главная страница клиники;
- информация о клинике и её преимуществах;
- каталог стоматологических услуг;
- подробные страницы отдельных услуг;
- каталог врачей и профили специалистов;
- информация о стоимости лечения;
- статьи, отзывы и ответы на часто задаваемые вопросы;
- контакты и карта клиники;
- адаптивная навигация для компьютеров и мобильных устройств.

2. Регистрация и авторизация

- регистрация пациента;
- проверка имени, email, телефона и пароля;
- безопасное хеширование пароля;
- подтверждение email шестизначным кодом;
- ограничение срока действия и количества попыток ввода кода;
- повторная отправка кода;
- вход по email и паролю;
- восстановление пароля;
- сохранение авторизации после обновления страницы;
- выход из учётной записи;
- разделение прав по ролям пациента, врача и администратора.

Авторизация основана на JWT. Токен передаётся через HttpOnly cookie, недоступный JavaScript-коду страницы. Пароли хранятся в базе данных только в виде bcrypt-хеша.

3. Онлайн-запись

Пациент последовательно выбирает стоматологическую услугу, врача, дату посещения и доступное время. После выбора врача и даты frontend запрашивает у backend список занятых интервалов. Недоступное и прошедшее время нельзя выбрать.

Backend повторно проверяет полученные данные, связывает запись с авторизованным пациентом и сохраняет её в MongoDB со статусом «ожидает подтверждения». Созданная запись отображается в личном кабинете пациента и панели администратора.

4. Личный кабинет пациента

- просмотр и редактирование данных профиля;
- подтверждение email;
- управление настройками уведомлений;
- просмотр собственных записей;
- доступ к медицинской информации;
- отмена доступных для отмены посещений;
- выход из учётной записи.

5. Панель администратора

- просмотр общей статистики клиники;
- отображение количества пациентов, врачей и записей;
- просмотр последних записей;
- экспорт отчётов в PDF;
- поиск и фильтрация записей;
- подтверждение, отмена и завершение приёмов;
- просмотр базы и карточек пациентов;
- просмотр истории посещений и медицинских документов;
- добавление и редактирование врачей;
- загрузка фотографий специалистов;
- создание и редактирование статей;
- публикация материалов и сохранение черновиков;
- модерация, одобрение, отклонение и удаление отзывов.

Административные API-маршруты дополнительно защищены серверной проверкой роли пользователя.

6. Кабинет врача

- расписание приёмов;
- рабочая статистика;
- информация о пациентах;
- работа с медицинскими данными;
- история лечения;
- рекомендации и медицинские документы.

7. Дополнительные возможности

- загрузка изображений и PDF-файлов;
- создание PDF-отчётов;
- уведомления о действиях с записями;
- карта клиники;
- адаптивная вёрстка;
- анимации интерфейса;
- SEO-настройки публичных страниц;
- документация API через Swagger;
- интеграция с почтовым сервером;
- дополнительные интеграции с Telegram и внешними сервисами при наличии настроенных ключей.


Архитектура проекта

Программа состоит из frontend и backend.

Frontend представляет собой одностраничное React-приложение:

- src/pages — страницы приложения;
- src/components — переиспользуемые компоненты интерфейса;
- src/context — глобальное состояние авторизации и записи;
- src/services — взаимодействие с данными;
- src/styles — общие стили и дизайн-система;
- src/lib — вспомогательные функции и статические данные.

Backend реализован как REST API на Node.js и Express:

- backend/routes — API-маршруты;
- backend/models — модели MongoDB;
- backend/middleware — авторизация и проверка ролей;
- backend/services — уведомления и внешние интеграции;
- backend/config — подключение к базе данных;
- backend/bot — интеграция с Telegram.

Frontend обращается к backend через маршруты /api. Во время разработки Vite перенаправляет эти запросы на сервер, работающий на порте 5000.

Системные требования

- Node.js версии 20 или новее;
- npm;
- доступ к MongoDB;
- современный браузер;
- SMTP-аккаунт для регистрации и подтверждения email.

Telegram, чат и другие внешние интеграции являются дополнительными и могут быть отключены.


Пошаговая инструкция по запуску

1. Распаковать архив с исходным кодом в отдельную папку.

2. Открыть терминал и перейти в корневую папку проекта:

   cd путь\к\папке\FamilyDent

3. Установить зависимости:

   npm install

4. Скопировать файл .env.example в .env:

   Copy-Item .env.example .env

5. Заполнить в .env обязательные параметры:

   PORT=5000
   MONGODB_URI=адрес_подключения_к_MongoDB
   JWT_SECRET=случайная_секретная_строка
   COOKIE_SECRET=случайная_секретная_строка
   SMTP_HOST=адрес_SMTP_сервера
   SMTP_PORT=587
   SMTP_USER=почтовый_аккаунт
   SMTP_PASS=пароль_приложения

Настоящие пароли, токены и ключи в архив с исходным кодом не включаются.

6. Убедиться, что порты 3000 и 5000 не заняты другими процессами.

7. Запустить frontend и backend одной командой:

   npm run dev:split

Также можно использовать:

   npm run dev

8. Открыть приложение в браузере:

   Frontend: http://localhost:3000
   Backend API: http://localhost:5000
   Документация API: http://localhost:5000/api-docs

9. Для создания production-сборки выполнить:

   npm run build

Собранные файлы будут помещены в каталог dist.


Оценка общей сложности

Общую сложность проекта я оцениваю как высокую.

Проект содержит frontend и backend, базу данных, ролевую модель доступа, регистрацию с подтверждением email, JWT-авторизацию, многоэтапную онлайн-запись, личные кабинеты, административные CRUD-интерфейсы, работу с медицинскими данными, файлами, PDF-отчётами и внешними сервисами.

Наиболее сложной частью стала система записи к врачу. Она связывает данные пациента, услуги, врача, даты и времени. Frontend получает занятые интервалы, блокирует недоступные варианты и отправляет выбранные данные на сервер. Backend повторно проверяет запрос, определяет пациента по авторизованной сессии, сохраняет запись и возвращает обновлённые данные пользователю.


Текущие ограничения

- для полноценной работы необходима доступная MongoDB;
- регистрация с подтверждением email требует настроенного SMTP;
- некоторые дополнительные функции зависят от внешних API;
- в программе пока отсутствует онлайн-оплата;
- для демонстрации необходимо заранее создать тестовые данные;
- требуется усиленная защита от параллельного бронирования одного интервала на уровне базы данных;
- для production-развёртывания необходимо настроить HTTPS, домен, CORS, безопасное хранение секретов и резервное копирование базы;
- отдельное мобильное приложение пока не разработано, используется адаптивная веб-версия.
