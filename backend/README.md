# Family Dent backend

Отдельное npm workspace `@familydent/backend`: Node.js + TypeScript, Express 5,
Mongoose 9. Runtime работает из скомпилированного `dist/` без `tsx`.

```text
backend/
  src/
    config/          проверка env и адресов интеграций
    database/        подключение, схема MongoDB, миграция старого сайта
    models/          строгие Mongoose-модели объявленных коллекций
    middleware/      постоянные лимиты запросов
    modules/
      auth/          аккаунты, сессии, пароли, CSRF
      content/       публичный контент и готовые медиа
      applications/  заявки и транзакционная очередь
      bot/           подписанный HTTP-мост и воркер доставки
      ai/            адаптеры нейросети и квоты
      admin/         заявки, очередь, контент, аудит
    lib/             общие функции
    types/           доменные типы
  scripts/           подготовка/проверка БД, создание admin, seed
  tests/             unit и интеграционные тесты
  deploy/            Compose и Caddy
  docs/              API, контракты и эксплуатация
```

## Данные и защита

MongoDB использует 18 коллекций контента и 12 служебных коллекций. Документы плоские,
со стабильными ID, датами BSON, статусом публикации и индексами. MongoDB-валидаторы
и Mongoose-модели строятся из одного объявления схемы. Runtime не меняет схему
и не создаёт индексы автоматически. DDL выполняется отдельно пользователем миграции;
пользователь приложения ограничен `familydent_web`.

Пароли: salted scrypt; старые website-хеши поддерживаются и обновляются при входе.
Случайный session token хранится в БД как SHA-256. В проде cookie имеет `HttpOnly`,
`Secure`, `SameSite=Lax` и префикс `__Host-`. TTL дополняется проверкой срока сессии.
Изменяющим запросам с сессией нужен CSRF-токен. В проде браузерным POST/PATCH нужен
точный разрешённый `Origin`.

Роли: `customer` видит собственные заявки; `staff` читает заявки и управляет
очередью; `admin` также редактирует контент. Публичная регистрация не принимает роль.
Изменения контента проверяют ревизию и создают аудит без копирования персональных
данных. Черновики и внутренние поля скрыты из публичного API. Для архивации служит
`publicationStatus=archived`.

Есть ограничение размера JSON, строгие входные схемы, постоянные лимиты запросов,
нормализация IPv6, точный CORS, Helmet/CSP, безопасные ошибки и журнал с request ID
без тел запросов и секретов. Ключи лимитов содержат HMAC IP вместо исходного IP.
`TRUST_PROXY` задаётся только адресами доверенного прокси.

Заявка и outbox-событие записываются одной транзакцией. Воркеры захватывают задачу
с арендой и уникальным токеном, повторяют временные ошибки, прекращают доставку
постоянных ошибок и дают оператору повторить `dead`-задачу с аудитом. Семантика
доставки — **at least once**: бот обязан дедуплицировать `eventId`.

## Команды из корня

| Команда                                                                  | Назначение                                                    |
| ------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `npm run dev`                                                            | API, ожидание readiness, затем Vite                           |
| `npm run dev:api`                                                        | API с автоматическим перезапуском                             |
| `npm run db:setup`                                                       | Валидаторы и индексы через migration credentials              |
| `npm run db:migrate`                                                     | Однократный перенос website-данных старой БД                  |
| `npm run content:seed`                                                   | Инициализация пустой БД bootstrap-контентом                   |
| `npm run db:verify`                                                      | Схемы, индексы, документы и связи                             |
| `npm run db:smoke`                                                       | Проверка API без записи данных                                |
| `npm run media:set-url -- "/images/a.webp" "https://cdn.example/a.webp"` | Назначение HTTPS URL существующему медиа                      |
| `npm run admin:create`                                                   | Новый admin из `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`  |
| `npm run build`                                                          | Проверки типов, сборка фронтенда и backend                    |
| `npm start`                                                              | Скомпилированный API с настройками backend/.env / process env |
| `npm run worker --workspace @familydent/backend`                         | Отдельный воркер; в API задайте `WORKER_ENABLED=false`        |

Учётные данные администратора передавайте через защищённое окружение или временный
ввод без эха, не через аргументы команды и не в Git. Существующий аккаунт CLI не
перезаписывает. Готового пароля администратора нет.

## Нейросеть

По умолчанию `AI_PROVIDER=disabled`. Для собственного OpenAI-совместимого сервера:

```dotenv
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://your-ai.example/v1
AI_MODEL=your-model
AI_API_KEY=
```

Для Ollama: `AI_PROVIDER=ollama`, `AI_BASE_URL=http://127.0.0.1:11434`,
`AI_MODEL=your-installed-model`, `INTEGRATIONS_ALLOW_HTTP=true`. В контейнере
`127.0.0.1` указывает на сам контейнер: нужен доступный приватный адрес сервиса.
Не публикуйте Ollama напрямую в интернет.

`POST /api/ai/chat` требует сессию и CSRF. Ограничены история, роли сообщений,
токены ответа, время запроса и суточная квота. Клиент не задаёт URL, модель, ключ,
system prompt или инструменты. В контекст добавляется только справка опубликованных
услуг. Бэкенд не сохраняет чат и не подмешивает заявки, пароли или данные аккаунта.
Текст, который пользователь отправил в чат, передаётся выбранной вами нейросети.
Ошибочные запросы к upstream тоже расходуют квоту.
