# Family Dent UI-kit

Все общие стили, компоненты и шрифты находятся в `src/ui-kit`. Импорт компонентов:
`@/ui-kit`. Глобальные стили подключаются один раз через `src/index.css`.
Палитра Family Dent сохранена: белый, песочный, графитовый и зелёный.

## Где менять дизайн

`tokens.css` — единственный источник значений палитры, шрифтов, размеров текста,
интервалов, радиусов, контейнеров, контролов, теней и брейкпоинтов.

- `--color-ink`, `--color-paper`, `--color-accent`, `--color-trust` — базовая палитра.
- `--color-text-primary`, `--color-text-secondary`, `--color-brand-text`,
  `--color-action-primary`, `--color-border-default` — семантические роли.
- `--font-display`, `--font-body`, `--font-mono` — семейства шрифтов.
- `--type-{variant}-mobile/tablet/desktop` — размеры конкретного варианта.
- `--type-{variant}-family/weight/leading/tracking` — его остальные свойства.

Например, изменение `--type-heading-2-mobile` меняет все заголовки этого варианта
на мобильных устройствах. Изменение `--font-display` меняет семейство всех
заголовков, использующих этот токен. Размеры указаны в `rem`, чтобы учитывать
выбранный пользователем размер текста.

Три режима типографики:

| Режим   | Условие                           |
| ------- | --------------------------------- |
| mobile  | Базовые значения                  |
| tablet  | От `--breakpoint-tablet` (48rem)  |
| desktop | От `--breakpoint-desktop` (64rem) |

Значения переключаются в том же `tokens.css` через Tailwind `@variant`.
В компонентах не нужно перечислять три размера. Дополнительные `sm`, `xl`, `2xl`
служат для композиции страницы, а не задают новую шкалу типографики.
Например, полная навигация включается с `xl`, когда для неё достаточно места.

## Типографика и семантика

| Вариант                  | Назначение                                |
| ------------------------ | ----------------------------------------- |
| display                  | Крупный акцент в разделе                  |
| hero                     | Заголовок первого экрана главной          |
| heading-1 … heading-6    | Иерархия заголовков                       |
| body-lg / body / body-sm | Вводный, основной и вспомогательный текст |
| caption                  | Примечания и метаданные                   |
| label                    | Подписи полей                             |
| overline                 | Короткие надзаголовки                     |
| button / input           | Текст контролов                           |
| stat                     | Числовые показатели                       |
| wordmark                 | Декоративная надпись бренда               |

```tsx
import { Heading, Text } from "@/ui-kit";

<Heading level={1}>Услуги клиники</Heading>
<Heading level={2} variant="display">Лечение без спешки</Heading>
<Text variant="body-lg" tone="secondary">Вводный абзац.</Text>
<Text as="span" variant="caption">Обновлено сегодня</Text>
```

`level` определяет реальный HTML-тег `h1`…`h6`, `variant` — только оформление.
Выбирайте уровень по структуре документа; визуальный размер его не меняет.
`Text` по умолчанию создаёт `p`, а `as` позволяет выбрать подходящий текстовый тег.
Один `<main>` уже находится в `App.tsx`, поэтому страницы не добавляют вложенный.

Для Motion-компонентов и нативных элементов доступны те же рецепты:
`className="type-heading-2"` или `typographyClass("body-sm", "secondary")`.
Локальный CSS может использовать `@apply type-body`; отдельно подключаемые
стили начинают с `@reference "../index.css"` (путь относительно файла).
Не добавляйте локальные `font-size`, `text-[…]` или отдельную responsive-шкалу.

## Контролы

```tsx
import { Button, ButtonLink, Field, Input, Select, Textarea } from "@/ui-kit";

<form onSubmit={handleSubmit}>
  <Field id="patient-name" label="Имя" hint="Как к вам обращаться" required>
    <Input name="name" autoComplete="name" />
  </Field>
  <Field label="Email" error={errors.email}>
    <Input name="email" type="email" autoComplete="email" />
  </Field>
  <Button type="submit" disabled={isSubmitting}>Отправить</Button>
</form>
<ButtonLink href="/services" variant="outline">Услуги</ButtonLink>
```

`Field` связывает одну подпись, подсказку и ошибку с одним `Input`, `Select` или
`Textarea` через `id`, `htmlFor`, `aria-describedby` и `aria-invalid`.
При необходимости задавайте `id` на `Field`; иначе создаётся уникальный ID.
Поля сохраняют нативные атрибуты, события, ref и участие в `FormData`.
Размер текста полей — не менее 1rem во всех трёх режимах.

`Button` по умолчанию имеет `type="button"`; отправка формы задаётся явно.
Варианты: `primary`, `secondary`, `outline`, `ghost`, `danger`.
Размеры: `sm`, `md`, `lg`. `ButtonLink` остаётся настоящей ссылкой.
У `IconButton` обязательна доступная подпись `aria-label`.

`Container` задаёт общую ширину и поля страницы. `width="content"` и
`width="readable"` ограничивают ширину контента и длинного текста.

## Цветовые контексты

На тёмной секции используйте `data-ui-scheme="inverse"`. Вложенная светлая
карточка возвращает обычные роли через `data-ui-scheme="default"`.
Компоненты с `tone="primary/secondary/brand"` и контурные кнопки учитывают контекст.
Цвета не копируются в страницы; для прозрачности используйте `color-mix` или
Tailwind opacity вместе с существующим токеном.

Размеры сеток, позиции изображений и композиция остаются в CSS страниц.
Общий внешний вид контролов принадлежит `controls.css`, текстовые рецепты —
`typography.css`, общие эффекты — `effects.css`. Для Canvas доступен
`readCssToken("--color-accent")`; JS читает фактическое значение CSS-токена.

## Каталог и проверка

В режиме `npm run dev` откройте `/ui-kit`: палитра, все варианты текста,
активные размеры для трёх режимов, состояния кнопок и полей, тёмный контекст.
Каталог и его маршрут исключаются из production-сборки.

Golos Text, Roboto Serif и IBM Plex Mono размещены в `assets/fonts` вместе
с лицензиями OFL. Загрузка шрифтов с Google во время посещения сайта не требуется.
Для замены семейства обновите `@font-face`, токен и лицензию соответствующих файлов.

Проверки: `npm run lint`, `npm test`, `npm run build`.
Тесты UI-kit проверяют семантику заголовков/ссылок, поведение кнопок,
связь подписей и ошибок с полями и уникальность ID.

Проверка от 22.10.2026: сборка, TypeScript, 27 обычных и 21 интеграционный тест
прошли. В Chromium проверены 11 страниц на ширинах 320, 768, 1024 и 1440px,
а также границы режимов типографики в каталоге. Горизонтальной прокрутки документа
и ошибок JavaScript не обнаружено. Проверка axe по правилам WCAG 2 A/AA и 2.1 AA
проведена для каталога, страниц, раскрытой навигации и формы записи.

Отправка форм с главной и страницы туризма проверена в production-сборке на
временной MongoDB: создаются заявка и соответствующая задача доставки боту.
Поля доступны по подписям; на экране 320×568 длинная форма прокручивается.
Шрифты проверены с кириллицей и латиницей; внешние запросы к Google Fonts
не используются. Тесты фронтенда также прошли на Node.js 22.12.
