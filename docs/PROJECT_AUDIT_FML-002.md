# Проверка проекта FML-002 — 22 октября 2026

## Вывод и решения

Часть блоков была избыточно высокой из-за размеров, не связанных с содержимым:
два экрана подряд на главной, большой знак на планшете, завышенные отступы
туристических секций и фотографии без определённой рамки. Уменьшать весь текст
или скрывать содержимое для сокращения страницы было бы неоправданно.

Сохранены палитра, семейства шрифтов, порядок секций и материалы клиники.
Изменены композиция первого экрана, размеры заголовков, вертикальные интервалы
и пропорции медиа. Длинные каталоги врачей и туристических направлений остаются
длинными по объёму содержимого; фильтры и полные профили сохранены.

## Исправленные ошибки

- Названия услуг обрезались в узких карточках. Текст участвует в расчёте
  высоты строки сетки, переносится и не пересекается со стрелкой.
- Фиксированная высота и абсолютное положение текста могли обрезать первый
  экран туризма. Текст теперь находится в потоке и увеличивает секцию.
- Галереи и декоративные панели получали высоту от исходных фотографий.
  Размер задаётся рамкой; изображения заполняют её через `object-fit`.
- В увеличенном тексте выходили за границы вопросы FAQ, метаданные результатов,
  контактные ссылки и шапки отзывов. Исправлены ограничения ширины и переносы.
- Плашка согласия на видео может увеличиваться вместе с текстом.
- На главной удалён дублирующий компонент врачей с длинным набором тегов.
  Общая карточка открывает профиль и передаёт выбранного врача в запись.
- В десктопных отзывах повторялись карточки, а скрытый overflow мешал чтению.
  Список теперь прокручивается мышью и клавиатурой, содержит по одной карточке
  на запись источника.
- Форма записи и авторизации используют общий нативный `Dialog`: модальность,
  Escape, восстановление фокуса до удаления элемента и прокрутка короткого окна.
  Профиль врача использует тот же lifecycle: переход к записи не снимает блокировку
  фона. Обычная запись сбрасывает выбранного ранее врача.
- В туристических пакетах исправлены роли текста на тёмном фоне с помощью
  существующих токенов inverse; добавлено доступное имя окна консультации.
- Добавлены ссылка перехода к содержимому, доступное состояние фильтров,
  защита шапки от скрытия при фокусе. Home/End слайдера больше не прокручивают
  одновременно страницу.
- Неизвестный URL показывает страницу 404 со ссылкой на главную. Статья
  показывает загрузку до ответа API; старый ответ не перезаписывает новый slug.

## Проведённые проверки

- TypeScript frontend/backend и browser-тестов, проверка неиспользуемых символов,
  production-сборки frontend/backend, `git diff --check`.
- 33 обычных теста и 21 интеграционный тест на отдельном MongoDB replica set:
  сессии, CSRF/Origin, права, валидация, лимиты, заявки/outbox, подписи бота,
  AI-адаптеры, административные операции и production-раздача.
- 113 тестов Chromium: 11 страниц × 6 ширин 320/390/768/1024/1440/1920;
  11 страниц с размером текста 200%; границы шкалы 767/768/1023/1024;
  короткое окно 844×390; геометрия галереи без изображений; управление
  клавиатурой, запись из профиля, загрузка статьи и неизвестный маршрут.
- В эту же серию входят 23 проверки axe: 11 страниц × 2 ширины и открытая
  форма записи, правила WCAG 2 A/AA, 2.1 AA, 2.2 AA. Автоматических нарушений
  в проверенных состояниях не найдено.
- Ручная проверка через управляемый браузер с рабочим API, фотографиями и
  обычным движением: появления, повторная прокрутка, фокус, reduced-motion,
  остановка Canvas вне экрана, очистка при SPA-переходе и печать.
- Отправка двух форм в production-сборке на временной MongoDB: одна запись и
  один outbox для каждой формы, ошибок JavaScript нет.
- `db:verify`: рабочая `familydent_web`, валидаторы, документы и индексы.
  `db:smoke`: readiness и все 18 типов публичного контента доступны.
  Тестовые заявки и пользователи в рабочей БД не создавались.
- `npm audit`, включая dev-зависимости: известных уязвимостей нет.
  Gitleaks по отслеживаемым и новым исходным файлам: утечек нет; локальные
  файлы окружения и приватные данные не включались в сканируемый снимок.

## Воспроизведение

```bash
npm ci --ignore-scripts
npx playwright install --with-deps chromium
npm run check
```

Для повторной проверки рабочей БД и API: `npm run db:verify` и `npm run db:smoke`.
Браузерные тесты используют production `dist` на отдельном порту 4173,
детерминированные публичные данные и блокируют внешние запросы. Они не требуют
ключей, Atlas, Telegram или изменения рабочей БД. Проверка настоящих форм и API
проводилась отдельно на изолированном replica set.

CI выполняет lint, тесты, сборку, аудит зависимостей, браузерную серию и сборку
Docker image. При падении браузерной проверки сохраняет screenshot и trace
на семь дней.

## Границы результата

Автоматические браузерные проверки выполнены в Chromium. Проверка axe не
заменяет проверку скринридером и оценку контраста каждого пикселя фотографии.
Это проверка проекта и исправления найденных проблем, а не сертификация WCAG.
Общий маршрут 404 работает внутри SPA; HTTP-статус страницы определяется
хостингом. Подключение настоящих Telegram/AI endpoint, DNS и production TLS
зависит от ещё не предоставленных параметров инфраструктуры. Контракты
адаптеров и обработка заявок проверены изолированно.
